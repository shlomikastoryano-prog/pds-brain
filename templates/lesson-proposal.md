# Lesson proposal (template)

Status: proposal, not yet reviewed.
Use: the comment-handling agent fills this in when a review comment has no matching lesson in the brain. A person checks it, then the reviewer approves it as a change request in the brain repo. See `guidelines/learning-loop.md`.
The agent never adds a lesson to the brain by itself.

## Copy from here

### <Short title: what to do, in a few words>
- **Do:** <what to do, one or two sentences>
- **Avoid:** <what not to do>
- **Why:** <the reason the reviewer gave. If no reason was given, write "reason not given in the comment". Do not invent one>
- **Example:** <a short illustration written from the comment, not copied code>
- Seen in: PR <number>

### Proposal details (remove before the lesson enters the brain)
- **Source comment:** <PR number and link to the comment>
- **Reviewer:** <who wrote it>
- **Occurrences:** <single occurrence | repeated, with the PR numbers>
- **Matching lesson in the brain:** <none | file and title of the closest one>
- **Missed despite a lesson:** <no | yes: which lesson, and the likely cause: not read, or unclear wording>
- **Fits our code:** <checked against phenom-ds: yes or no, with the files looked at. Write "to be verified" if not checked>
- **Target file:** <lessons/by-reviewer/<file> or guidelines/<file>, and the position>
- **Person's decision:** <general lesson | one-time preference | needs discussion>

## How to fill it in
- Keep the Do / Avoid / Why / Example format used in the existing lessons.
- Write a lesson the agent can act on. "Write clean code" is not a lesson.
- If the closest existing lesson only needs a clearer sentence, propose an edit to it instead of a new lesson.
